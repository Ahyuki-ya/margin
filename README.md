# margin 麻雀

ブラウザで遊べる4人打ちのリーチ麻雀です。

- **オンライン版（GitHub Pages）**: ブラウザだけで CPU 3 人と対戦できます。
  https://ahyuki-ya.github.io/margin/
- **LAN 対戦**: 1 台の PC がホストになり、同じ Wi-Fi の人がブラウザから参加します。4 人に満たない席には CPU が入ります。

PC とスマホの両方で遊べます。スマホで誤って牌を捨てないよう、1 回目のタップで牌を選び、2 回目のタップで捨てます。

## LAN 対戦の始め方（ホスト役の PC）

[Node.js](https://nodejs.org/) 22.18 以上が必要です。

```bash
npm install
npm start
```

起動すると、次のような案内が表示されます。

```
  このPC:        http://localhost:8080
  同じWi-Fiの人: http://192.168.x.x:8080
```

- ホスト自身は `http://localhost:8080` を開きます。
- ほかの人には `http://192.168.x.x:8080` を開いてもらいます。
- 名前を入れて参加すると、最初に入った人がホストになり、対局を開始できます。
- 対局の牌譜は `logs/` フォルダに保存されます。

ポート番号は `PORT=3000 npm start` のように変えられます。つながらない場合は、ホスト PC のファイアウォールで Node.js の通信が許可されているか確認してください。

## ルール

標準的な日本のリーチ麻雀（天鳳・雀魂に近いもの）です。

| 項目 | 内容 |
|---|---|
| 人数 | 4 人打ち |
| 長さ | 半荘戦 / 東風戦（選択） |
| 持ち点 | 25,000 点持ち・30,000 点返し、ウマ 10-20 |
| 赤ドラ | あり（各色 1 枚、なしも選択可） |
| 喰いタン・後付け | あり |
| 一発・裏ドラ・槓ドラ | あり（明槓・加槓のドラは打牌後にめくる） |
| ダブロン | あり（三家和は流局）。本場と供託は上家取り |
| 途中流局 | 九種九牌・四風連打・四家立直・四開槓・三家和 |
| 流し満貫 | あり |
| 数え役満 | あり（13 翻以上） |
| 切り上げ満貫 | なし |
| ダブル役満 | なし（四暗刻単騎・国士十三面なども役満 1 倍）。異なる役満の複合はあり |
| 包（パオ） | 大三元・大四喜 |
| 飛び | あり（0 点未満で終了） |
| 延長戦 | 30,000 点に届かなければ西入（東風戦は南入） |
| アガリ止め・テンパイ止め | あり（オーラスの親がトップかつ 30,000 点以上なら終了） |
| 喰い替え | 禁止 |
| リーチ後の暗槓 | 待ちが変わらない場合のみ可 |

## CPU の強さ

- **よわい（ランダム）**: 和了できるときは和了し、それ以外はランダムに捨てます。
- **ふつう**: 向聴数（聴牌までの距離）が小さくなるように捨て、聴牌したらリーチします。役牌だけポンします。

## 開発

```bash
npm install
npm run dev        # 画面の開発サーバー（CPU 対戦のみ）
npm test           # テスト（点数計算・対局の進行）
npm run typecheck  # 型チェック
npm run build      # dist/ に公開用のファイルを作る
npm run selfplay -- --games 100 --cpu greedy,greedy,random,random --out logs/selfplay
```

`main` ブランチに push すると、GitHub Actions がテストしてから GitHub Pages に公開します（リポジトリの Settings → Pages → Source を「GitHub Actions」にしておく必要があります）。

### フォルダ構成

```
src/engine/   ルール（画面に依存しない。ブラウザでも Node でも動く）
  tile.ts       牌の表現
  hand.ts       和了形・待ち・向聴数
  score.ts      役の判定と点数計算
  game.ts       対局の進行（ステートマシン）
  view.ts       各プレイヤーから見える情報
  log.ts        牌譜の形式と再生
src/ai/       打ち手（ランダム CPU・向聴数 CPU・人間）
src/runner.ts ルールと打ち手をつなぐ進行役
src/client/   画面（タイトル・卓・CPU 対戦・LAN 対戦）
src/net/      LAN 対戦の通信メッセージ
server/       LAN 対戦のサーバー
scripts/      自己対戦
tests/        テスト
```

### 牌譜と学習について

牌譜は「乱数の種＋全員の行動を起きた順に並べたもの」です。`replay()` で再生すると対局を完全に再現できるので、学習用の特徴量は後から牌譜を再生しながら計算します。特徴量の設計を変えても、集めたデータを無駄にせずに済みます。

CPU はすべて「見えている情報（`PlayerView`）と選べる行動 → 行動」という同じ形（`Agent`）なので、学習したモデルもこの形で差し替えられます。
